Política de privacidad.

Información sobre el tratamiento de datos en Chronix 0.2.0, en especial los datos obtenidos de los servicios de Google.

1. Responsable y alcance

Chronix es un proyecto personal de organización desarrollado y gestionado por aiglea01. La aplicación se ejecuta en una instancia autoalojada. Esta página pública es exclusivamente informativa: no permite registrarse ni iniciar sesión en la instalación privada.

Contacto para dudas de privacidad o solicitudes relacionadas con datos: alvaroiglesiasavila01@gmail.com.

Este texto describe el funcionamiento técnico de Chronix 0.2.0. Las personas que desplieguen su propia instancia deben adaptar los datos de contacto, los proveedores utilizados y la política a su instalación.

2. Qué datos utilizamos y para qué

Identidad de Google

Al iniciar sesión se solicitan los permisos openid, email y profile para obtener un identificador de cuenta, nombre y dirección de correo verificada, y crear una sesión de Chronix.

Datos creados en Chronix

Los calendarios propios, eventos, notas y sus metadatos se almacenan para ofrecer las funciones de agenda y sincronización.

Datos de Google Calendar, solo con permiso adicional

Al conectar una cuenta de Calendar, se solicita el permiso https://www.googleapis.com/auth/calendar.readonly para consultar los calendarios accesibles y sus eventos, incluidos títulos, fechas, horas, descripciones, ubicaciones y enlaces disponibles.

La finalidad de acceso a datos de Google es exclusivamente permitir el inicio de sesión y mostrar los calendarios que el usuario haya autorizado. No se utilizan esos datos para publicidad ni para crear perfiles comerciales.

3. Cómo funciona la conexión con Google Calendar

La conexión con Calendar es voluntaria y distinta del inicio de sesión. Chronix obtiene un token de renovación para recuperar nuevos tokens de acceso sin solicitar permiso en cada consulta. El permiso solicitado es de solo lectura: la versión 0.2.0 no crea, modifica ni elimina eventos de Google Calendar.

El servidor consulta la API de Google Calendar utilizando el token de acceso del usuario. El contenido devuelto se usa para presentar los calendarios y eventos en la interfaz de Chronix. La desconexión de una cuenta elimina de la base de datos la credencial de renovación asociada a esa conexión.

Puedes revocar la autorización también desde las conexiones de terceros de tu cuenta de Google. La revocación desde Google puede impedir nuevas consultas, pero no borra automáticamente todas las copias que pudieran quedar almacenadas en tu navegador.

4. Dónde se almacenan los datos

  • Servidor privado y SQLite: identificadores y perfiles de usuario, registros propios de Chronix, sesiones y cuentas de Google conectadas. Los tokens de renovación de Calendar se guardan cifrados mediante AES-256-GCM.
  • Memoria del servidor: las consultas recientes de Google Calendar se conservan temporalmente en una caché en memoria, normalmente durante dos minutos.
  • Navegador: la aplicación utiliza localStorage para conservar los datos propios, cambios pendientes de sincronización, preferencias y una copia en caché de los calendarios y eventos de Google consultados. Estos datos pueden permanecer incluso después de cerrar sesión hasta que sean eliminados.
  • Cookies de sesión: Chronix utiliza cookies técnicas HttpOnly, SameSite=Lax y, cuando se sirve por HTTPS, Secure. La sesión tiene una duración máxima configurada de 30 días.

La versión revisada no envía los contenidos de Google Calendar a la base de datos SQLite como registros de Chronix; se consultan a través de la API y se conservan temporalmente como se describe arriba.

5. Con quién se comparten los datos

Chronix no vende datos personales ni los comparte con anunciantes. Las consultas de identidad y calendario implican comunicación con servicios de Google para realizar las funciones autorizadas. El acceso a la aplicación privada está mediado por la infraestructura de red configurada por quien la aloja, actualmente Tailscale en la instalación personal.

Esta web informativa se aloja en GitHub Pages, que puede procesar datos técnicos de visitas según sus propias condiciones. La página informativa no incluye scripts de analítica propios, formularios de captura de datos ni cookies publicitarias creadas por el sitio. La aplicación privada y esta web pública son servicios distintos.

6. Medidas de protección

Chronix emplea OAuth 2.0 con PKCE y protección del estado de autenticación, cookies de sesión y comprobación de origen para operaciones de modificación. Las credenciales de renovación se cifran en el servidor. La instalación personal está diseñada para utilizar HTTPS y restringir el acceso de red mediante Tailscale.

Ningún sistema garantiza un riesgo nulo. No compartas copias exportadas de Chronix, tokens, archivos de configuración ni capturas que contengan información privada. En dispositivos compartidos, utiliza perfiles de navegador separados o borra los datos locales al terminar.

7. Conservación, desconexión y eliminación

Los eventos y notas propios de Chronix permanecen en la base de datos hasta que se eliminen o se solicite su supresión al responsable de la instancia. Al borrar un registro desde la aplicación se modifica el conjunto de datos sincronizados. Las copias de seguridad del servidor pueden conservar información anterior durante el período que aplique el administrador.

Al desconectar Google Calendar se elimina la credencial de conexión de la base de datos, pero para retirar la autorización completamente también puedes revocarla desde tu cuenta de Google. Cerrar sesión invalida la sesión del servidor, pero no garantiza que se borren los datos guardados en el navegador. Para eliminarlos localmente, borra los datos del sitio web desde la configuración de tu navegador.

Chronix 0.2.0 no incluye un panel de autoservicio para borrar toda una cuenta de usuario del servidor. Para solicitar la eliminación completa, contacta con el administrador de la instancia.

8. Tus derechos y contacto

Para solicitar acceso, rectificación, exportación o eliminación de datos de una instancia administrada por el responsable indicado, escribe a alvaroiglesiasavila01@gmail.com. Si utilizas una instalación de Chronix gestionada por un tercero, dirige la solicitud a su administrador.

Esta política podrá actualizarse si cambian las funciones, los permisos de Google o los mecanismos de tratamiento. La fecha de actualización se mostrará al inicio de la página. Se aplicarán los derechos que correspondan según la normativa vigente.

Resumen: Google se utiliza para identificar al usuario y, cuando lo autoriza, para mostrar Google Calendar en modo solo lectura. Los datos de organización propios se almacenan en el servidor de Chronix; parte de los datos pueden conservarse localmente en el navegador.
